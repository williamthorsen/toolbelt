## 0.3.0 — 2026-11-16

### 🎉 Features

- Adds `isPreapproved` to `ToolServer`, which makes `runPrompt` allow each call of that server's tools once without consulting `permissionPolicy`, on a profile that can identify such a call. (#680)
- Adds an optional `isToolServerCall` to `AgentProfile`, which reports whether a permission request calls a tool on a named MCP server, and defines it in `claudeCodeProfile` and `antigravityProfile` but not in `codexProfile`; the Antigravity version matches the call's title, so it also accepts a server whose name extends the given one with `_`. (#680)

## 0.2.0 — 2026-11-15

### 🎉 Features

- Adds an initial `runPrompt` to `@williamthorsen/toolbelt.acp/proposed`, which starts an agent command, runs one prompt on it through the Agent Client Protocol (ACP) v1 while refusing every permission request, and yields each update from the agent followed by a `stopped` event that contains the stop reason and any reported token usage and cost. (#637)
- Adds `AgentRunError`, with which `runPrompt` rejects when the agent cannot be started, breaks the protocol, or exits during the run, and which records the command, the exit code or signal, and the end of the agent's stderr. (#637)
- Adds the `permissionModeId` field to `AgentProfile`, which makes `runPrompt` switch the session to the named permission mode before it sends the prompt and fail the run when the session does not list that mode. (#638)
- Adds the `permissionPolicy` option to `runPrompt`, a sync or async function typed by the exported `PermissionPolicy`, which grants a permission request once when it returns `'allow'`, refuses the request once for any other result, and cancels the turn and fails the run when it throws. (#638)
- Adds the `tools` option of `runPrompt` and its `ToolServer` type, which pass an app's MCP server, built with the new peer dependency `@modelcontextprotocol/server`, to the agent over MCP-over-ACP, a loopback HTTP endpoint, or a stdio bridge, whichever the agent advertises first. (#639)
- Adds the `claudeCodeProfile`, `antigravityProfile`, and `codexProfile` factories, which return an `AgentProfile` that names the harness's command, sign-in, and permission mode and, for Claude Code and Antigravity, keeps the user's settings, hooks, plugins, and MCP servers out of the session. (#640)
- Adds an optional `sessionMeta` field to `AgentProfile`, which `runPrompt` sends as `_meta` on `session/new` to pass harness-specific session options that ACP does not standardize. (#640)

### 🏗️ Internal features

- Adds `packages/acp` as the `@williamthorsen/toolbelt.acp` workspace, which is cloned from `packages/_template`, exports nothing from any of its tiers, and is registered in `.config/release-kit.config.ts`, `.github/labels.yaml`, `.meta/label-map.json`, and the `pnpm-lock.yaml` importers. (#636)

### 📚 Documentation

- Documents in `AgentRunError` that a harness that is not signed in fails with a `RequestError` cause whose `code` is `-32000`, as observed from Claude's adapter. (#640)
